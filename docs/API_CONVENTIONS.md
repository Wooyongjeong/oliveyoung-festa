# API 응답 규약

## 성공 응답

모든 성공 응답은 HTTP 상태와 함께 `ApiResponse<T>` 형식을 사용한다.

```json
{
  "statusCode": "EVENT_001",
  "statusMessage": "이벤트 목록 조회 성공",
  "body": []
}
```

- `statusCode`: 클라이언트가 분기할 수 있는 안정적인 업무 코드
- `statusMessage`: 사용자 또는 개발자가 이해할 수 있는 기본 메시지
- `body`: API별 응답 데이터

HTTP 상태는 전송 결과를 표현하고 업무 코드는 도메인별 결과를 표현한다. 본문의 업무 코드에 HTTP 숫자를 중복해 넣지 않는다.

## 오류 응답

오류는 추적과 필드 오류 정보를 위해 기존 `ApiError` 형식을 유지한다.

```json
{
  "code": "AUTH_401",
  "message": "로그인이 필요합니다.",
  "requestId": "request-id",
  "details": {}
}
```

## 현재 상태 코드

| 코드 | HTTP | 의미 |
|---|---:|---|
| `COMMON_001` | 200 | 일반 요청 처리 성공 |
| `AUTH_001` | 200 | 개발 로그인 성공 |
| `AUTH_002` | 200 | 로그인 사용자 조회 성공 |
| `EVENT_001` | 200 | 이벤트 목록 조회 성공 |
| `EVENT_002` | 200 | 이벤트 상세 조회 성공 |
| `ORDER_001` | 201 | 주문 생성 성공 |
| `ORDER_002` | 200 | 내 주문 목록 조회 성공 |
| `COMMON_400` | 400 | 요청값 검증 실패 |
| `AUTH_401` | 401 | 인증 필요 또는 유효하지 않은 인증 |
| `AUTH_403` | 403 | 접근 권한 없음 |
| `EVENT_404` | 404 | 이벤트를 찾을 수 없음 |
| `ORDER_409` | 409 | 판매 기간 밖 또는 유효하지 않은 등급으로 주문 불가 |
| `INVENTORY_409` | 409 | 선택 티켓 매진 |
| `PURCHASE_409` | 409 | 사용자·이벤트별 단일 주문 제한 |
| `IDEMPOTENCY_409` | 409 | 같은 멱등성 키의 요청 본문 충돌 |
| `COMMON_500` | 500 | 서버 내부 오류 |

새 코드는 `<도메인>_<일련번호>` 형식을 사용한다. 기존 코드의 의미를 바꾸거나 다른 결과에 재사용하지 않는다.
